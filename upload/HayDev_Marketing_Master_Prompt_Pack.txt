5. PROVIDER REGISTRY
======================================================================

Создай единый AIProviderRegistry.

Capability types:

LLM
WEB_RESEARCH
IMAGE_GENERATION
IMAGE_EDIT
VIDEO_GENERATION
VIDEO_CONTINUATION
VIDEO_IMAGE_TO_VIDEO
TTS
VOICE_CLONING
VOICE_CONVERSION
MUSIC_GENERATION
AVATAR_VIDEO
TRANSCRIPTION
TRANSLATION
EMBEDDINGS
MODERATION

Каждый adapter должен реализовывать единый contract:

interface ProviderAdapter {
  providerId: string;
  capabilities: Capability[];

  validateConfig(): Promise<ValidationResult>;
  healthCheck(): Promise<HealthResult>;

  estimateCost?(request: unknown): Promise<CostEstimate>;

  submit(request: unknown): Promise<ProviderJob>;
  getStatus(jobId: string): Promise<ProviderJobStatus>;
  getResult(jobId: string): Promise<ProviderResult>;

  cancel?(jobId: string): Promise<void>;
}

Provider Registry хранит:
- provider;
- model;
- capability;
- API status;
- supported languages;
- supported durations;
- reference-image support;
- continuation support;
- aspect ratios;
- max input/output limits;
- estimated cost;
- timeout;
- retry policy;
- fallback order;
- provider-specific constraints.

Перед реализацией конкретного adapter:
1) открыть актуальную официальную документацию API;
2) проверить model ID;
3) проверить endpoint;
4) проверить auth;
5) проверить async job mechanics;
6) проверить webhook/polling;
7) проверить rate limits;
8) проверить supported media inputs;
9) проверить supported languages;
10) проверить pricing;
11) проверить коммерческие условия;
12) только после этого включать adapter.

Никогда не предполагать capability по названию модели.

17. SCENE CONTINUITY
======================================================================

После успешной сцены:

1. сохранить исходный result;
2. извлечь последний пригодный кадр;
3. сохранить как continuity asset;
4. использовать его как next-scene reference, если API модели это поддерживает;
5. передать Character Bible;
6. передать Style Bible;
7. сгенерировать следующую сцену.

Не утверждать continuity, если конкретная модель/API это не поддерживает.

Если модель поддерживает start/end frame:
использовать эту capability.

Если нет:
использовать semantic continuity через:
- character references;
- style references;
- same wardrobe;
- same environment;
- same camera grammar;
- same color palette.

======================================================================
84. DEFINITION OF DONE
======================================================================

Функция считается DONE только если:
- реализована end-to-end;
- UI работает;
- backend работает;
- persistence работает;
- authorization есть;
- validation есть;
- errors обрабатываются;
- loading state есть;
- tests есть;
- tests PASS;
- happy path проверен;
- failure path проверен;
- i18n проверен;
- mobile/desktop проверены;
- documentation обновлена;
- no fake/mocked production behavior.

87. NO-DUPLICATION RULE
======================================================================

Перед созданием любого нового:
- service;
- adapter;
- API route;
- component;
- DB entity;
- provider registry;
- queue;
- prompt subsystem;

сначала найди существующую реализацию.

Переиспользуй или рефактори.
Не создавай второй competing implementation.

======================================================================
88. NO-FAKE-COMPLETION RULE
======================================================================

Запрещено писать:
DONE
COMPLETE
PRODUCTION READY

если:
- используется mock вместо реального production path;
- API adapter не проверен и заявлен как verified;
- кнопка существует, но backend не работает;
- status hardcoded;
- publication не подтверждена;
- tests skipped;
- build broken;
- credentials отсутствуют и это скрыто.

Используй честные статусы:

IMPLEMENTED
IMPLEMENTED_NOT_LIVE_VERIFIED
LIVE_VERIFIED
BLOCKED_EXTERNAL
FAILED
DEGRADED
